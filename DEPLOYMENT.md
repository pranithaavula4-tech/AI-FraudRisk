# Deployment Guide — GitHub, Public URL, and Demo Video

This covers, in order: (1) pushing the project to a GitHub repository,
(2) deploying it to a public URL — with a recommended platform plus AWS
and alternative options, (3) recording and publicly hosting a 5-minute
demo video, and (4) a final checklist tying it all together.

---

## Why not Vercel

Vercel is built for static sites and short-lived serverless functions
(Next.js, etc.). Streamlit is a **long-running Python process** that
holds an open websocket connection to the browser for the whole session
— that model doesn't fit Vercel's serverless execution (functions there
are expected to finish in seconds and don't hold persistent connections).
You *can* deploy Vercel for a future Next.js/React frontend if you ever
rebuild the UI that way, but for this Streamlit app, use one of the
options below instead.

**Recommended order:**
1. **Streamlit Community Cloud** — free, made specifically for this, public URL in ~2 minutes. Start here.
2. **AWS App Runner** — since you already have AWS; a proper production-style deployment using the bundled `Dockerfile`.
3. **Render / Railway** — good free-tier fallbacks if you want a non-AWS container host.

## Part 1: Push the project to GitHub

### 1.1 Create the repository
1. Go to https://github.com/new
2. Name it (e.g. `fraud-spike-detector`), keep it **Public** (needed for
   Streamlit Community Cloud's free tier and for anyone to view your
   deployed app's source), don't initialize with a README (you already have one).
3. Click **Create repository** — GitHub will show you a remote URL like
   `https://github.com/<your-username>/fraud-spike-detector.git`.

### 1.2 Push your local project
From inside the `fraud-spike-detector/` folder on your laptop:

```bash
git init
git add .
git commit -m "Initial commit: fraud-spike detector pipeline + Streamlit app"
git branch -M main
git remote add origin https://github.com/<your-username>/fraud-spike-detector.git
git push -u origin main
```

If `git push` asks for a password, GitHub no longer accepts your account
password directly — you need a **Personal Access Token**:
1. https://github.com/settings/tokens → **Generate new token (classic)**
2. Scope: `repo`. Copy the token.
3. When prompted for a password during `git push`, paste the token instead.

(Or use `gh auth login` if you have the GitHub CLI installed, then push normally.)

### 1.3 What's committed vs. generated
- **Committed**: `config.py`, `src/`, `app.py`, `data/creditcard.csv`,
  `requirements.txt`, `Dockerfile`, `README.md`, tests, this guide.
- **NOT committed** (`.gitignore`'d): `models/*` and `results/*` — these
  are generated by `train.py`/`evaluate.py`. `app.py` automatically
  regenerates them on first load if they're missing (see
  `ensure_artifacts()` in `app.py`), so every deployment always runs a
  fresh, reproducible training pass instead of shipping stale binaries.

Verify what will be pushed before you commit:
```bash
git status
```
You should NOT see `models/xgb_fraud_spike_model.joblib` or
`results/metrics_report.json` in the list (only `.gitkeep` placeholders
for those folders).

## Part 2: Deploy — Option A (recommended): Streamlit Community Cloud

Free, zero infrastructure, and gives you a public `*.streamlit.app` URL.

1. Go to https://share.streamlit.io and sign in with GitHub.
2. Click **Create app** → **From existing repo**.
3. Select your `fraud-spike-detector` repo, branch `main`, main file path `app.py`.
4. Click **Deploy**.
5. First load will take 1-3 minutes: Streamlit Cloud installs
   `requirements.txt`, then `app.py`'s `ensure_artifacts()` trains the
   model and computes the cost-optimal threshold automatically (you'll
   see the "First-time setup..." spinner in the app itself).
6. You'll get a public URL like:
   `https://<your-username>-fraud-spike-detector-app-xxxxxx.streamlit.app`
   This is publicly visible to anyone with the link — perfect for your
   video and for sharing.

**If it fails to build**, check the "Manage app" logs panel — the most
common cause is a `requirements.txt` version not being available for
the Python version Streamlit Cloud uses; if so, relax the pin (e.g.
`xgboost>=2.1.1` instead of `==2.1.1`) and push again — it auto-redeploys
on every push to `main`.

## Part 3: Deploy — Option B: AWS App Runner (uses your AWS account)

App Runner is the simplest AWS path for "I have a container, give me a
public HTTPS URL" — no VPC/load balancer/EC2 management needed.

### 3.1 Push the image to Amazon ECR
```bash
# From the fraud-spike-detector/ folder, with the AWS CLI configured
# (aws configure) and Docker installed and running:

aws ecr create-repository --repository-name fraud-spike-detector --region <your-region>

aws ecr get-login-password --region <your-region> | \
  docker login --username AWS --password-stdin <account-id>.dkr.ecr.<your-region>.amazonaws.com

docker build -t fraud-spike-detector .
docker tag fraud-spike-detector:latest <account-id>.dkr.ecr.<your-region>.amazonaws.com/fraud-spike-detector:latest
docker push <account-id>.dkr.ecr.<your-region>.amazonaws.com/fraud-spike-detector:latest
```
Replace `<your-region>` (e.g. `ap-south-1`) and `<account-id>` with your
own values (`aws sts get-caller-identity` shows your account ID).

### 3.2 Create the App Runner service
1. AWS Console → **App Runner** → **Create service**.
2. Source: **Container registry** → **Amazon ECR** → select the
   `fraud-spike-detector:latest` image you just pushed.
3. Deployment trigger: **Manual** (or automatic if you want it to
   redeploy whenever you push a new image).
4. Service settings: port `8501` (matches the `EXPOSE 8501` in the
   Dockerfile). CPU/memory: 1 vCPU / 2 GB is enough for this project.
5. Click **Create & deploy**. App Runner gives you a public URL like:
   `https://xxxxxxxxxx.<region>.awsapprunner.com`
6. First request after deploy will trigger `ensure_artifacts()` inside
   the container (same one-time training step as Streamlit Cloud).

### 3.3 (Alternative) Plain EC2, if you'd rather not use ECR/App Runner
```bash
# On a fresh Ubuntu EC2 instance (t3.medium or larger recommended):
sudo apt-get update && sudo apt-get install -y docker.io
sudo systemctl enable --now docker
git clone https://github.com/<your-username>/fraud-spike-detector.git
cd fraud-spike-detector
sudo docker build -t fraud-spike-detector .
sudo docker run -d -p 80:8501 --restart unless-stopped fraud-spike-detector
```
Then open the instance's **security group** to allow inbound traffic on
port 80 from `0.0.0.0/0`, and visit `http://<ec2-public-ip>/` in a
browser. For a real domain + HTTPS, put this behind an Application Load
Balancer with an ACM certificate, or use Caddy/nginx with Let's Encrypt
in front of the container.

## Part 4: Alternative free container hosts (if you skip AWS)

Both of these auto-detect the `Dockerfile` with zero extra config:

**Render** (https://render.com):
1. New → **Web Service** → connect your GitHub repo.
2. Render detects the `Dockerfile` automatically.
3. Set the port to `8501` if not auto-detected.
4. Deploy — you get a `https://fraud-spike-detector.onrender.com`-style URL.

**Railway** (https://railway.app):
1. New Project → **Deploy from GitHub repo**.
2. Railway detects the `Dockerfile` automatically and deploys.
3. Under **Settings → Networking**, click **Generate Domain** to get a
   public `https://....up.railway.app` URL.

## Part 5: Record and publicly host a 5-minute demo video

### 5.1 Suggested script (fits comfortably in 5 minutes)
| Time | What to show |
|---|---|
| 0:00–0:30 | One sentence on the problem: detecting fraud "spikes" — bursts of activity — not just single suspicious transactions. |
| 0:30–1:30 | Open the repo on GitHub — quickly show `config.py` (schema flexibility), `src/feature_engineering.py` (velocity features), and the README's cost-model section. |
| 1:30–3:30 | Switch to the **live deployed URL**. Walk through the app: pick a known-fraud transaction, show its score, the velocity features that drove it, and the cost-optimal threshold decision. Then pick a normal transaction to contrast. |
| 3:30–4:30 | Show the `results/pr_curve.png` and `results/cost_vs_threshold.png` (either from the repo or a `results/` folder view in the app/GitHub) and explain the cost-optimal threshold in one sentence. |
| 4:30–5:00 | Close with the defense-only statement and known limitations (bundled synthetic data, proxy entity ID) — shows rigor/honesty, which matters for a hackathon judge. |

### 5.2 Recording tools
- **Loom** (https://loom.com) — easiest option. Free tier records
  screen + optional webcam, auto-generates a shareable public link the
  moment recording stops. No separate upload/hosting step needed.
  - Install the Loom browser extension or desktop app → **Start Recording**
    → select "Screen + Cam" or "Screen only" → do your walkthrough →
    stop → Loom gives you a link like `https://www.loom.com/share/xxxxxxxx`.
  - Go to the video's **Share** settings and confirm visibility is set
    to **"Anyone with the link"** (public) rather than restricted to your workspace.
- **OBS Studio** (https://obsproject.com, free, all platforms) — more
  control, records to a local `.mp4` file. Use this if you want to edit
  before publishing.

### 5.3 Making it publicly visible (if you used OBS or want a second copy)
Upload the recorded `.mp4` to **YouTube**:
1. https://studio.youtube.com → **Create** → **Upload video**.
2. Set visibility to **Public** or **Unlisted** ("Unlisted" is still
   viewable by anyone with the link, just not searchable — either
   satisfies "publicly visible via link" for a hackathon submission;
   choose **Public** if you want it discoverable).
3. Copy the share link once processing finishes.

Either a Loom link or a YouTube link works — pick whichever is easier
for your submission form to accept (some hackathon portals only accept
YouTube links; check before you record).

## Part 6: Final checklist

- [ ] `git push` succeeded; repo is public on GitHub
- [ ] `.gitignore` confirmed `models/`/`results/` binaries are NOT in the repo (`git status` / check on GitHub's file browser)
- [ ] Deployed app loads at a public URL and the first-load spinner successfully trains the model (check the app, not just that the URL responds)
- [ ] App's sidebar shows a PR-AUC and cost-optimal threshold (confirms `ensure_artifacts()` ran successfully)
- [ ] Demo video recorded, ≤5 minutes, visibility set to public/unlisted
- [ ] You have three links ready to submit: **GitHub repo URL**, **deployed app URL**, **video URL**
